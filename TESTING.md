# Проверка сборки 1.0.0

Проверено 25 октября 2026 на Minecraft Java 26.3, Fabric Loader 0.19.5, Java 25, в отдельном тестовом мире.

## 28 проверок внутри игрового клиента

- Survival и заблокированный Hard, граница ровно 16 блоков.
- Натуральное дерево в выбранном чанке; проверяется вся высота, включая Y=319.
- Ожидание до ввода и старт таймера; запрет добычи и изменения блоков снаружи, Creative, смены сложности и телепортации наружу.
- Пауза исключается из активного времени, но учитывается в полном.
- Команда `/reset` создаёт новую попытку, очищает инвентарь, восстанавливает все исходные состояния блоков; обе таблицы существуют в мире.
- Последний сундук и вода мешают финишу. Только воздух и бедрок завершают попытку, снимают границу и записывают результат.
- Сохранение содержит таймеры и финиш; `/reset` работает после финиша.
- После выхода и повторного входа сохраняется ID попытки; время вне мира исключается из активного таймера и включается в полный.

Подробный результат — `TEST-REPORT.txt`. Старт и финиш фиксируются на игровых тиках. Визуальное положение таблиц не подтверждено скриншотами: захват игрового окна завершался тайм-аутом; существование двух текстовых сущностей и их настройки проверены в коде и при запуске.

## 5 тестов публикации и приёмника

Проверены анонимная отправка без авторизации игрока, повторная отправка одного ID, отказ при изменении уже принятого результата, проверка типов и ника, игнорирование клиентского подтверждения, подтверждение только из файла модерации и обработка Windows-переносов строк.

Проверена реальная цепочка: мод → публичный HTTPS-приёмник → GitHub Issues → GitHub Actions → `records.json` и неподтверждённая таблица. Повторный вход отправил результат, ожидавший после временного сетевого сбоя. Технические попытки перечислены в `moderation.json:testOnly` и скрыты из рейтинга.

Тестовые миры и вспомогательный тестовый мод находятся отдельно от установленной сборки и в релизный JAR не включены. Рабочие миры CommentDrop не использовались.

## Эксплуатация

Профиль TLauncher использует 3 ГБ памяти, ZGC и два доступных процессора для Java. Такая конфигурация прошла повторные запуски; без ограничения числа потоков наблюдались сбои JVM на этом компьютере.

Приёмник работает на компьютере владельца через бесплатный туннель с автоматическим переподключением. Он не является круглосуточным хостингом. При выключенном компьютере таблицы читаются из GitHub, отправка ждёт следующего входа или обновления после восстановления приёмника. Discord для ручной проверки видео пока не создан.
