# Чанк на скорость — Minecraft Java 26.3

Мод Fabric 1.0.0. Профиль TLauncher: **ChunkSpeedrun-26.3**. Его игровая папка — `instance` рядом с этим описанием. Для запуска нужен Java 25; Fabric Loader 0.19.5 уже указан в установленном профиле. Fabric API не требуется.

## Начать

1. Перезапустить TLauncher, выбрать **ChunkSpeedrun-26.3** и запустить игру.
2. В главном меню нажать **«Чанк на скорость»** в левом верхнем углу. Создаётся обычный мир со случайным сидом, структурами, Survival, заблокированной сложностью Hard, без читов и бонусного сундука.
3. Дождаться сообщения о готовности чанка. Мод находит ближайший чанк с натуральными брёвнами, листвой и безопасной точкой появления. После выбора этот чанк становится стартовым.
4. Записать видео всей попытки, если нужен подтверждённый результат. Первое движение мыши, клавиша движения или прыжка запускает таймер. Добыча и использование предметов также запускают его, чтобы нельзя было добывать до старта.
5. Очистить все 16×16 блоков по всей высоте мира, включая верхний слой Y=319. Допустимы только воздух и бедрок. Жидкости, листва, растения, сундуки, факелы и блоки игрока мешают финишу. Предметы и мобы не мешают.

Основной таймер считает реальное время игры вне настоящей паузы Minecraft. Инвентарь и чат не ставят одиночный мир на паузу. В скобках — полное календарное время от старта до финиша, включая паузы и закрытую игру. Выход сохраняет основной таймер; полное время продолжает идти. Перевод системных часов может исказить полное время — модерация должна сверяться с видео.

Смерть сейчас использует обычное возрождение; попытка и время сохраняются. Это техническое поведение текущей версии, отдельного правила дисквалификации за смерть пока нет.

До финиша нельзя выйти из чанка, добывать/использовать блоки снаружи, менять режим, сложность или мир командами. Взрывы и поршни не могут добывать соседние блоки, вода и лава не протекают через границу чанка. После финиша граница и ограничения команд снимаются; сложность разблокируется. Читы сами по себе не включаются.

## Команды

- `/reset` — восстановить исходные блоки, блок-сущности (в том числе содержимое сундуков), исходных сущностей и время суток; очистить инвентарь, эндер-сундук, опыт и эффекты; вернуть здоровье и голод; начать ожидание новой попытки. Уже записанные результаты сохраняются. Действует и после финиша. Постройки внутри чанка будут заменены исходным чанком.
- `/leaderboard` — обновить обе таблицы и повторить отправку ожидающих результатов.

Две таблицы располагаются на пять блоков выше самого высокого оставшегося блока чанка и перемещаются вниз по мере выкапывания. Текст поворачивается к игроку, виден сквозь блоки; дальность отображения увеличена. Записи сортируются по основному времени. Слева — подтверждённые, справа — неподтверждённые. При каждом входе в мир мод загружает обе таблицы из GitHub и повторяет отправку ожидающих результатов. Дополнительное обновление — каждые 30 секунд игры и по `/leaderboard`. Без сети используется кэш и локальные результаты.

## Данные и сохранение

- `instance/saves/<мир>/chunkspeedrun/run.json` — состояние попытки и оба таймера.
- `instance/saves/<мир>/chunkspeedrun/initial.nbt` — исходные блоки чанка, блок-сущности и сущности для `/reset`. Снимок рассчитан на эту фиксированную версию игры и набор модов; не переносить его между разными версиями.
- `instance/chunkspeedrun-results/*.json` — результаты с идентификатором попытки. Рядом появляется `.sent` после успешной отправки.
- `instance/config/chunkspeedrun.json` — имя GitHub-репозитория; адрес приёмника определяется из него автоматически.

Неотправленные результаты отправляются повторно при входе, по `/leaderboard` и каждые 30 секунд игры. Разрыв сети не удаляет результат. Не использовать `/reset` после постройки, которую хотите сохранить: сначала скопировать весь мир из `saves`. Для будущей сборки общего мира сохраняйте мир вместе с видео и ID попытки. Мод не отправляет миры или видео автоматически.

## GitHub и анонимная отправка

Репозиторий: **https://github.com/Xvobuk/chunk-speedrun**. Игрокам не нужны GitHub, GitHub CLI, вход в аккаунт или лицензия Minecraft. Подойдут обычные ники из 3–16 латинских букв, цифр и `_`.

Мод отправляет ник, оба времени, ID попытки и версию правил в анонимный HTTPS-приёмник. Приёмник создаёт GitHub Issue с заявкой; собственной базы у него нет. GitHub Actions обновляет `records.json` и `leaderboard.json`. Результат появляется после выполнения workflow, обычно с небольшой задержкой. `submission-endpoint.json` содержит текущий адрес приёмника, поэтому менять мод при смене туннеля не нужно.

На компьютере владельца репозитория приёмник запускается так (GitHub CLI уже авторизован; нужны Python 3.10+ и стандартный Windows OpenSSH Client):

```powershell
.\Start-Receiver.ps1
```

Приёмник работает в фоне на компьютере Вадима через публичный HTTPS-туннель Pinggy. Бесплатный туннель ограничен часом: скрипт переподключается и публикует новый адрес автоматически. Компьютер должен оставаться включённым. После перезагрузки запустить скрипт снова. Не устанавливается автозапуск Windows. Пока приёмник выключен, таблицы остаются доступны из GitHub, а новые результаты ждут отправки на компьютерах игроков. Для работы круглосуточно тот же приёмник можно перенести на постоянный хостинг.

Конфигурация игроков по умолчанию:

```json
{"repository":"Xvobuk/chunk-speedrun","submissionEndpoint":""}
```

Токен GitHub в мод не встраивается и игрокам не передаётся. Приёмник использует локальную авторизацию владельца только для фиксированных операций с заявками в этом репозитории. Поля клиента `status` и любые заявления о подтверждении игнорируются. Адреса клиентов не сохраняются в базе или журнале приёмника; временные ограничения частоты используют их только в оперативной памяти. GitHub и Pinggy видят соединения как внешние провайдеры.

## Модерация

Новый результат всегда неподтверждённый. Для подтверждения после просмотра полного видео без читов и багоюза модератор с правом записи в репозиторий копирует объект результата из `records.json` в массив `verified` файла `moderation.json` и делает коммит. Workflow перенесёт точную копию результата в подтверждённую таблицу. Это отдельный файл с правами репозитория: ни содержимое заявки, ни её метка, ни запрос игрока не могут подтвердить результат.

Массив `rejected` содержит ID отклонённых попыток, `testOnly` — ID технических тестов; они скрываются из обеих таблиц. Удаление записи из `verified` возвращает её в неподтверждённые, если она не отклонена. Первый принятый результат сохраняется неизменно: редактирование Issue не меняет зафиксированные времена. Discord-сервер ещё не создан, его адрес в мод не выдуман. Видео передаётся модераторам вручную после его создания. Проверка честности и принадлежности ника опирается на видео и модератора: одиночный клиент и неподтверждённая таблица допускают поддельные заявки, которые нельзя считать подтверждёнными рекордами.

## Исходники и сборка

Исходники мода — `src/`, приёмника — `receiver/`, публикации таблиц — `scripts/`. Игра с 26.3 использует открытые имена классов; этот небольшой мод собирается напрямую JDK 25 без переименования классов и без Fabric API. Скрипт проверяет SHA-1 официального клиентского JAR 26.3.

```powershell
.\Build.ps1 -JavaHome C:\path\to\jdk-25
python -m unittest discover -s scripts -v
```

Мод предназначен для одиночного мира. Совместное прохождение по LAN и игра на выделенном Minecraft-сервере в этой версии не поддерживаются. Полный античит, Discord-бот и объединение миров — отдельные будущие компоненты.

Остальные сборки, миры и базы CommentDrop не изменялись.
